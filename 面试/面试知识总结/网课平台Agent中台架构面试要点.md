# 网课平台 Agent 中台架构面试要点

## 面试前 2 分钟速记

> [!summary] 先背这 10 句
> 1. **项目定位**：传统网课微服务负责业务，Agent 中台负责理解需求、编排任务和调用能力。
> 2. **三种路由**：业务网关分接口，中台网关管 AI 入口，意图路由选 Agent。
> 3. **三层身份权限**：认证用户、认证调用应用，再校验具体资源权限。
> 4. **权限贯穿调用链**：AppKey 不能代替用户授权；查订单看归属，查讲义看购课权限。
> 5. **限流看四项**：请求频率、活跃并发、模型 Token、单任务执行预算。
> 6. **令牌桶不是模型 Token**：前者控制准入，后者衡量模型输入输出用量。
> 7. **Agent 执行循环**：模型决策 → 运行环境执行工具 → 结果回填 → 继续或结束。
> 8. **RAG 查资料，工具查实时业务**：价格和订单状态走业务 API；未授权资料不能进入模型上下文。
> 9. **协议分工**：Function Calling 表达工具调用，MCP 接入工具与上下文，A2A 交互智能体任务。
> 10. **失败处理**：超时不等于未执行；下单要幂等；断开流式连接不等于任务自动结束。

## 项目介绍：30 秒口述

> 这个方案是在网课售卖和课程讨论微服务上接入 Agent 中台。原有系统负责用户、课程、交易、学习记录和讨论；AIGC 服务连接中台，由入口网关完成应用认证、用户授权校验和限流，再通过意图路由选择购课、咨询、答疑、推荐或讨论助手。助手结合知识库和业务工具完成任务，业务服务负责最终的权限与业务规则校验。设计重点是把用户权限贯穿调用链，并控制模型消耗和任务并发。

口述时结合自己实际实现的部分说明；图中内容属于架构方案。

## 架构与请求链路

```text
前端 → Nginx → 业务网关 → AIGC 接入服务
     → 中台入口网关（认证、授权、限流）
     → 意图路由 / 编排 → 专业 Agent
     → 按需调用模型、RAG、业务工具 → 结果回填 / 返回

工具 → 携带用户授权调用业务服务 → 资源与业务规则校验
```

## 高频问答

### 1. 为什么需要两个网关？意图路由又是什么？

| 位置 | 核心职责 |
| --- | --- |
| 业务 API 网关 | 用户入口；按路径转发课程、交易、讨论和 AI 请求 |
| 中台入口网关 | AI 平台入口；应用认证、用户授权、配额、任务并发准入 |
| 意图路由 | 结合问题和上下文，在已授权的 Agent 中选择处理能力 |

**两层网关是本方案的职责拆分，不是所有项目都必须部署两个。** 中台独立服务多个应用时，单独治理更清楚。意图路由处理语义选择，不承担权限裁决。

补充：网关做路由转发；Feign 是服务端 HTTP 客户端。参考：[Spring Cloud Gateway 工作原理](https://docs.spring.io/spring-cloud-gateway/reference/spring-cloud-gateway-server-webflux/how-it-works.html)。

### 2. 鉴权怎么落地？只在网关验 JWT 行不行？

**不够。认证确认身份，授权决定允许访问什么。**

- **业务网关**：验证用户凭证，检查接口权限。
- **中台网关**：验证调用应用，同时校验用户授权及 Agent 访问范围。
- **工具与业务服务**：校验订单归属、课程购买权限、讨论操作权限。
- **RAG、会话与缓存**：按用户和资源权限隔离，避免其他用户的数据被带入上下文。

JWT 要验证签名、有效期、签发方和目标服务；用户身份从可信凭证中获得，不能直接信任传入的 `userId`。服务间传递可验证、适用于目标服务的授权凭证。

**面试例子**：用户让购课助手查询别人的订单，即使中台应用认证通过，订单服务仍须拒绝访问。参考：[Spring Security JWT 校验](https://docs.spring.io/spring-security/reference/servlet/oauth2/resource-server/jwt.html)。

### 3. 怎么限流？为什么只限制入口 QPS 不够？

一次用户请求可能触发多次模型调用、工具调用和子任务，入口请求数不能代表实际消耗。

| 控制项 | 本项目中的做法 |
| --- | --- |
| 请求频率 | 网关按应用、已认证用户、接口限流；匿名入口可按 IP 粗限流 |
| 活跃并发 | 控制运行中任务和 SSE 连接数，保护连接及执行资源 |
| 模型用量 | 控制模型请求次数、Token 配额与用户使用额度 |
| 单任务预算 | 限制执行轮数、工具次数、子 Agent 并行数；重试也计入 |

**Redis 令牌桶**：按速率补充令牌，请求原子扣减；不足时拒绝，可允许有限突发。多实例共享 Redis 状态，避免各自放行造成总量超限。超限一般返回 `429`。

令牌桶令牌与模型 Token 分开计量。模型输出用量事前未知，可先预留预算并限制最大输出，完成后按实际消耗结算；并发名额要在任务结束或取消后释放。

参考：[Gateway Redis 限流器](https://docs.spring.io/spring-cloud-gateway/reference/spring-cloud-gateway-server-webflux/gatewayfilter-factories/requestratelimiter-factory.html)。

### 4. Agent 到底怎么执行？工作流和 Agent 有什么区别？

**Agent** 根据模型判断和执行结果决定下一步；**工作流** 按预设路径运行，两者可以组合。

```text
加载上下文 → 模型决定回答或调用工具
→ 运行环境校验并执行工具 → 结果回填
→ 再次判断，直到完成、失败或达到预算
```

模型负责提出工具调用，程序实际执行；权限与参数校验由代码完成。模糊问题先追问，明确的问题路由到对应助手，复合任务再考虑拆分协作。

参考：[Agent 与工作流的区别](https://www.anthropic.com/engineering/building-effective-agents)。

### 5. RAG 和业务工具怎么分工？如何保护付费资料？

- **RAG**：查讲义、课程 FAQ、政策文档；入库时解析、切分、建立索引，问答时检索、重排并携带引用。
- **业务工具**：查当前价格、订单状态、已购课程，或执行创建订单等操作。
- **权限控制**：检索范围依据购课权限约束，返回材料在进入模型前完成授权过滤；共享缓存也要考虑权限隔离。

**例子**：“这一章是什么意思”走课程资料检索；“我买了哪些课”调用业务接口。RAG 能提供依据，仍需检查回答是否忠于资料；资料不足时说明缺少依据或追问。

### 6. Function Calling、MCP、A2A 有什么区别？

| 概念 | 一句话回答 | 项目例子 |
| --- | --- | --- |
| Function Calling | 模型输出工具名与结构化参数，由运行环境执行 | 请求查询当前用户订单 |
| MCP | 标准化工具和上下文接入 | 通过 MCP Server 暴露业务能力 |
| A2A | 标准化独立智能体之间的任务交互 | 编排器委派任务给答疑 Agent |

**AgentCard 是身份、能力、端点和认证要求的描述，不是执行代码。** A2A 的 Task 用于跟踪任务状态，Artifact 表示产物。多个逻辑 Agent 不一定需要 A2A，进程内调用或普通服务接口也可以实现协作。

参考：[A2A 核心概念](https://a2a-protocol.org/latest/topics/key-concepts/)、[MCP 架构](https://modelcontextprotocol.io/docs/learn/architecture)。

### 7. 会话历史、长期记忆、检查点有什么区别？

| 概念 | 保存什么 |
| --- | --- |
| 会话历史 | 当前对话的消息和工具结果 |
| 长期记忆 | 经筛选保留的跨会话偏好或事实 |
| 检查点 | 执行流程中的状态，用于暂停、恢复和追踪 |

LangGraph 可用于状态编排和检查点恢复。恢复流程时，已经产生副作用的工具操作仍要防止重复执行；检查点不自动保证业务“只执行一次”。

参考：[LangGraph 核心能力](https://docs.langchain.com/oss/python/langgraph/overview)。

### 8. 模型或工具失败怎么办？如何避免重复下单？

- **失败分类**：超时、暂时不可用可有限重试；参数错误或权限不足应返回明确原因。
- **幂等写入**：订单创建使用业务幂等键和数据库唯一约束等机制，重复调用返回已有结果。
- **熔断与降级**：熔断控制是否继续调用异常依赖；降级决定失败后怎样响应。不能把下单失败包装成成功。
- **流式与取消**：SSE 提供增量返回；断连后由任务策略决定取消还是后台继续，取消需传播到下游并释放资源。
- **可观测性**：追踪一次用户请求关联的 Agent、模型和工具调用，观察成功率、耗时、重试次数与费用。

**追问速答**：超时只是调用方没及时收到结果，业务可能已经执行。应先按幂等键查询或安全重试，不能直接再创建一笔订单。
